═══════════════════════════════════════
WHAT YOU ARE BUILDING — READ THIS FIRST
═══════════════════════════════════════

You are building the complete frontend dashboard for an 
AI Dialogue Enhancer system. This is Module 8 of a larger 
system. The backend API is already built and running. Your 
job is to build the web interface that the author uses 
every day to review conversations, approve response drafts, 
manage their knowledge base, and monitor their feedback 
history.

───────────────────────────────────────
THE SYSTEM CONTEXT
───────────────────────────────────────

The AI Dialogue Enhancer helps a coach and author participate 
more thoughtfully in online conversations across social media 
platforms including Reddit, Bluesky, Mastodon, Discord, 
Telegram, Threads, YouTube, Facebook, LinkedIn, and Instagram.

The backend does the following automatically:
- Monitors social media platforms for relevant conversations
- Searches the author's 15 years of writing to find relevant 
  ideas using RAG (Retrieval Augmented Generation)
- Analyses each conversation to decide if the author should 
  comment or not
- Generates 3 to 4 response drafts in different styles 
  grounded in the author's own writing
- Stores everything in a PostgreSQL database via Supabase

The dashboard is where the author spends 10 to 15 minutes 
each day. They open it, see today's shortlisted conversations 
with ready-made response drafts, and approve, edit, or reject 
each one. Approved responses are posted to the platform 
automatically.

This is not a busy social media management tool. It is a 
calm, focused, single-user interface designed for deep 
reading and thoughtful decision making. The design must 
reflect that.

───────────────────────────────────────
THE BACKEND API
───────────────────────────────────────

The backend is a Python FastAPI server. All endpoints 
return this response envelope:

{
  "success": boolean,
  "data": object or null,
  "error": string or null,
  "timestamp": ISO timestamp string
}

The base URL is read from environment variable:
NEXT_PUBLIC_API_URL

All API calls are made from the frontend using fetch 
or axios. There is no authentication system yet — 
this is a single user private tool so no login is 
required for the MVP.

Available backend endpoints:

KNOWLEDGE BASE:
GET    /knowledge/documents
GET    /knowledge/documents/{id}
POST   /knowledge/upload (multipart)
DELETE /knowledge/documents/{id}
POST   /knowledge/documents/{id}/reindex
GET    /knowledge/documents/stats

CONVERSATIONS:
GET    /conversations
GET    /conversations/{id}
POST   /conversations/submit

DRAFTS:
POST   /drafts/{id}/approve
POST   /drafts/{id}/edit-and-approve (body: edited_content)
POST   /drafts/{id}/reject (body: rejection_reason optional)
POST   /drafts/{id}/save
POST   /drafts/{id}/mark-posted
GET    /drafts/feedback-summary

Build lib/api.ts as a centralised API client module.

Create an axios instance with:
- baseURL from NEXT_PUBLIC_API_URL environment variable
- Content-Type application/json header as default
- 30 second timeout
